# Retain direct atom admission after the bounded experiment

**Rejected.** Moving atom work admission into its two owners saved deadline
polls in viability preparation, but slowed the primary ordinary/finite Count
routes. Keep the existing shared predicate's direct charge. The <=10% allowance
does not make an extra mechanism worthwhile when it widens the main parity gap.
No runtime or specification change survives this experiment.

One [predeclared](PREDECLARED.md) [public comparison](comparison.json),
**104.584 seconds**, quiet Ubuntu VM/.NET11RC3, CPUmask4. Exact clean `ff0185ea`
before, the archived two-file proposal after. Sixteen Count/IsMatch cases, four
equal-result lanes, warm1s/min64, independent60ms calibration, five alternating
samples, minimum **59.837ms**. Complete result batches checked after timing.
No confirmation or further variant. Allocations unchanged in every measured lane.

[All paired samples/spreads](summary.json) support the decision without another
run: the main region and category penalties are stable; controls hardly move.
The deadline benefit does not justify the default/finite penalty and added
per-atom dispatch. These A/B observations do not replace published snapshot rows.

[Correctness](verification.json) passed on net10/net11. Eleven complete production
[before](state-before.jsonl)/[after](state-after.jsonl) probes retain identical
viability bits, preparation/single-search work, ranges/capture hashes, modeled
peak working capacity and final13B enclosing loans. The prototype was correct;
its operating-cost tradeoff was unsuitable.

Twelve independent interruption witnesses remain in the existing test fixture:
both search routes admit the first category block before executing it and stop
before a further block after expiry; final simple atoms cannot publish after
original-token cancellation or deadline expiry. Focused Core658/runtime passes
again after reverting the proposal. Existing source `ff0185ea` CI41277110235 is
GREEN on Windows/Linux. No package/catalog qualification was repeated.

Live VM benchmark Core DLL and PDB were restored by an affected-project build
and compare byte-for-byte with the original baseline (Core DLL SHA256
`CEF93A88D00525AC72C3012BAA9A6972B595684158AE1BF5672A74E3E77975B0`).
